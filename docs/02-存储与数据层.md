# 步骤 2：存储与数据层

> 目标：完成全部文件存储能力（SAF 授权、扫描、meta 读写、编号、移动/删除/改名），不涉及任何界面。UI 步骤（03~05）将调用本层的能力。
> 前置：步骤 1 完成。

## 一、数据模型（`data/model/`）

```kotlin
@Serializable
data class ItemMeta(
    val id: Int,          // 编号
    val name: String,     // 事项名称（不含编号前缀）
    val year: Int,        // 时间-年
    val month: Int,       // 时间-月（1..12）
    val important: Boolean = false,   // 是否重要（星标）
)
```

- 对应存储文件 `.meta.json`（kotlinx-serialization 读写，UTF-8）。
- 运行时包装类 `Item`（内存中用）：`meta: ItemMeta`、`folder: DocumentFile`、`files: List<DocumentFile>`（文件夹内除 `.meta.json` 外的所有文件）。

## 二、存储位置与授权（`data/settings/SettingsStore.kt`）

- 用 `EncryptedSharedPreferences` 持久化三样：**存储目录 Uri 字符串**、**API Key**、**模型名**（默认 `glm-4.6v-flash`）。
- 提供读取接口：`getRootUri() / saveRootUri(uri)`、`getApiKey() / saveApiKey(key)`、`getModel() / saveModel(model)`。本步先实现存储目录部分；API Key 和模型名留到步骤 5 实现（07 会用到）。
- 说明：设置页（步骤 5）用 `ACTION_OPEN_DOCUMENT_TREE` 选目录并调用 `takePersistableUriPermission()` 获取持久授权，把 Uri 字符串存到这里；**本步只需把存储/读取接口写好**。

## 三、StorageManager（`data/storage/StorageManager.kt`，单例/可注入）

全部基于 SAF 的 `DocumentFile.fromTreeUri(context, rootUri)` 操作，禁止直接使用 `java.io.File`。

### 1. 目录扫描
- `listItems(): List<Item>`：遍历根目录子目录，
  - **跳过 `remove` 目录**（不区分大小写）；
  - 只认**含 `.meta.json`** 的文件夹为事项；
  - meta 读取失败/损坏 → 按默认值容错：名称 = 文件夹名去掉 `编号-` 前缀后的部分（解析不出就取文件夹名），时间 = 当前年月，important = false，id 解析失败记 0；
  - 每个事项内文件列表 = 子目录中除 `.meta.json` 外的文件（按添加时间倒序，见 00 总览）。

### 2. 编号分配
- `nextId(): Int`：收集所有事项的 id，从 1 开始取**第一个未被使用**的编号。注意：解析失败的 id=0 事项不参与分配。

### 3. 创建事项
- `createItem(name, year, month): Item`：分配编号 → 在根目录创建文件夹，名称 = `"%03d-%s".format(id, name)`（编号补零 3 位，如 `001-房租`）→ 写入 `.meta.json`。
- 名称的非法字符（`\ / : * ? " < > |`）校验放在 UI 层（步骤 3/5），本层**防御性再清洗一次**（替换为 `_`）。

### 4. 改名（事项）
- `renameItem(item, newName)`：只改名称部分，**编号不变**；先检查新文件夹名不与根目录现有文件夹撞名（撞名返回错误）；`DocumentFile.renameTo(newFolderName)` 改文件夹名 + 重写 `.meta.json`。两步都成功才算成功。

### 5. 移入文件（手机文件 → 事项文件夹）
- `addFile(item, sourceUri): AddFileResult`：
  - 读取源文件（`contentResolver` 打开输入流），写入事项文件夹下新文件（`DocumentFile.createFile(mime, displayName)`）；
  - **重名处理**：目标文件夹内已有同名文件 → 自动在扩展名前加 `(1)`、`(2)`…（如 `截图(1).jpg`）；
  - **删除源文件**：复制成功后调用源 Uri 的 delete（`contentResolver.delete`，若源是 DocumentFile 则 `delete()`）；删除失败 → 返回结果标记"已复制但无法删除原件"，UI 据此提示用户；
  - 返回结果包含：成功与否、新文件引用、是否需要提示"未删原件"。

### 6. 删除
- `deleteFile(item, file)`：把文件移入 `remove/`（`remove` 目录不存在则先创建）——即复制进 remove + 删除原文件；remove 内已有同名 → 文件名自动加 `-yyyyMMdd` 后缀（如 `截图-20260801.jpg`）。
- `deleteItem(item)`：**整个事项文件夹移入 remove**（保留 `001-xxx` 结构）；remove 内已有同名文件夹 → 加 `-yyyyMMdd` 后缀。
- 移入 remove 用"复制 + 删除"还是 renameTo 看实现：同一授权树内 `DocumentFile.renameTo` 优先（原子、快）；renameTo 失败再退回复制+删除。

### 7. 切换重要
- `toggleImportant(item)`：改 meta 的 `important` 并重写 `.meta.json`。

### 8. 时间修改
- `changeTime(item, year, month)`：改 meta 并重写。

### 9. 排序
- 排序规则写在数据层（UI 直接用排好的列表）：重要项在前 → 组内时间倒序（year 倒序，同年比 month 倒序）→ 编号升序。

### 10. 文件改名（详情页用，接口留到步骤 4 实现）
- `renameFile(item, file, newName)`：**保留扩展名**——只允许改主名部分，自动补回原扩展名；新主名不能是 `.meta.json` 的主名 `meta`（防止与元数据文件撞名）；目标重名 → 自动加 `(1)`。

## 四、辅助工具（`util/`）

- `FileType`：按扩展名/MIME 分类——图片（jpg/jpeg/png/gif/bmp/webp）、pdf、txt（含 md）、其他。供缩略图图标和 AI 输入构造使用。

## 五、验证方式（本步没有 UI）

- 在 MainActivity 里**临时**加一个按钮（步骤 3 会替换掉），点击后依次执行：创建 3 个事项（含重名场景）→ 打印扫描结果 → 编号分配 → 改名 → 删除一个事项 → 移入一个文件 → 打印 remove 目录内容，用日志确认各规则生效。验证完删掉临时代码（或保留到步骤 3 开始前）。
- 建议在真机上测试（SAF 需要真实的文件系统）。

## 六、边界情况清单（实现时逐条对照）

- [ ] remove 目录不存在时自动创建
- [ ] meta 文件损坏/缺失时容错，不崩溃
- [ ] 文件夹名无编号前缀（用户手动建的）→ id=0，不参与编号分配，排序放最后
- [ ] 添加文件时目标已有 `截图.jpg` → 生成 `截图(1).jpg`
- [ ] 移入 remove 撞名 → 加 `-yyyyMMdd` 后缀
- [ ] 复制成功但删源失败 → 返回提示标记，UI 提示"已复制但无法删除原件"
- [ ] 编号分配跳过已删除事项（remove 里的不算）
