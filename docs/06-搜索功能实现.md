# 步骤 6：搜索功能实现

> 目标：把主页面搜索框接通——输入关键词实时过滤事项列表。**这是倒数第二步；AI 在下一步实现。**
> 前置：步骤 3~5 完成（主页面搜索框 UI 已就绪）。

## 一、功能规则

1. **过滤范围**：关键词匹配
   - 事项名称（包含即命中，**忽略大小写**）；
   - **或** 任一文件名（匹配事项文件夹内任意文件名，忽略大小写）。
2. **排序不变**：过滤后的结果仍按 重要置顶 → 组内时间新→旧 → 编号升序。
3. **空关键词**（或全空白）→ 显示全部事项。
4. **实时过滤**：输入即过滤（事项数量级小，不需要防抖）。
5. 搜索框的清除按钮 → 清空关键词恢复全量列表。

## 二、实现要点

### MainViewModel（在步骤 3 基础上扩展）

```kotlin
private val _query = MutableStateFlow("")
val query: StateFlow<String> = _query
fun onQueryChange(q: String) { _query.value = q }

// 过滤逻辑
val filteredItems: StateFlow<List<Item>> = combine(items, query) { list, q ->
    val kw = q.trim()
    if (kw.isEmpty()) list
    else list.filter { item ->
        item.meta.name.contains(kw, ignoreCase = true) ||
        item.files.any { it.name?.contains(kw, ignoreCase = true) == true }
    }
}.stateIn(viewModelScope, WhileSubscribed(5000), emptyList())
```

### MainScreen（步骤 3 的搜索框接通）

- 搜索框 `value = viewModel.query`，`onValueChange = viewModel::onQueryChange`；
- 列表数据源从 `items` 换成 `filteredItems`。

### 性能提示

- 事项数量几百以内直接 `filter` 即可；文件名匹配需要读取文件夹内文件列表（StorageManager.listItems 已返回，直接用 `item.files`，无需重新扫描）。
- 搜索状态下删除/改名事项：操作成功后 `load()` 重新扫描，过滤自动重算（无需特殊处理）。

## 三、验收清单

- [ ] 输入关键词 → 事项名称命中的事项出现，不命中的消失
- [ ] 输入文件名关键词（如 `截图`）→ 含该文件的事项被搜出
- [ ] 大小写不敏感（如 `room` 能搜到 `ROOM` 相关事项名）
- [ ] 清空搜索框 → 恢复全部事项
- [ ] 搜索状态下结果排序仍正确（重要置顶、时间、编号）
- [ ] 搜索状态切换重要/改名后列表正确刷新
