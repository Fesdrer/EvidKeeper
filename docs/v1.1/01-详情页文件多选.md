# v1.1 步骤 1 — 详情页文件多选

## 一、目标

进入事项详情页后点击底部「添加文件」，系统文件选择器支持**一次勾选多个文件**（可跨目录），批量复制进事项文件夹，完成后汇总提示结果。

## 二、改动点

### 1. `ui/detail/DetailScreen.kt`

**① 文件选择器改多选**（原第 72-76 行）：

```kotlin
// 选择文件（支持多选）
val filePickerLauncher = rememberLauncherForActivityResult(
    ActivityResultContracts.OpenMultipleDocuments()
) { uris ->
    if (!uris.isNullOrEmpty()) viewModel.addFiles(uris.toList())
}
```

> 回调类型是 `Array<Uri>?`：取消返回 `null`，全不选返回空数组，两分支都被判空覆盖。

**② 收集进度状态**（与其它 collectAsState 并列）：

```kotlin
val isAdding by viewModel.isAdding.collectAsState()
```

**③ 底部按钮加禁用态与进度**（原第 134 行）：

FilledTonalButton(

### 2. `ui/detail/DetailViewModel.kt`

删除原 `addFile(uri)` 方法（唯一调用方是 DetailScreen，已同步改造），替换为批量方法：

```kotlin
// 批量添加文件进行中
private val _isAdding = MutableStateFlow(false)
val isAdding: StateFlow<Boolean> = _isAdding.asStateFlow()

// ── 添加文件（支持多选批量） ──
fun addFiles(uris: List<Uri>) {
    val it = _item.value
    if (it == null) {
        _toastMessage.value = "事项不存在"
        return
    }
    if (uris.isEmpty() || _isAdding.value) return

    _isAdding.value = true
    viewModelScope.launch {
        var success = 0
        var failed = 0
        var needCleanup = false
        // 后台逐文件复制，避免大文件阻塞主线程
        withContext(Dispatchers.IO) {
            uris.forEach { uri ->
                val r = storageManager.addFile(it, uri)
                if (r.success) {
                    success++
                    if (r.needPromptDeleteSource) needCleanup = true
                } else {
                    failed++
                }
            }
        }
        load() // 只刷新一次，避免 N 次全目录扫描
        _isAdding.value = false
        _toastMessage.value = when {
            failed == 0 && !needCleanup -> "已添加 $success 个文件"
            failed == 0 -> "已添加 $success 个文件，但部分原文件无法删除，请手动清理"
            success == 0 -> "添加失败：$failed 个文件未能复制"
            else -> "已添加 $success 个，$failed 个失败"
        }
    }
}
```

新增 import：`androidx.lifecycle.viewModelScope`、`kotlinx.coroutines.Dispatchers` / `launch` / `withContext`。

## 三、设计决策

| 决策 | 理由 |
|---|---|
| 循环复用 `StorageManager.addFile()`，不合并批量方法 | 每文件失败语义独立（复制失败/删源失败/同名 `(1)` 后缀），`StorageManager` 零改动 |
| 结果走现有 `toastMessage` 流（Toast）而非 Snackbar | 页面已消费 toastMessage，无需引入 snackbarHost |
| `load()` 只刷新一次 | 避免 N 次 `listItems()` 全目录扫描 |
| 复制移入 `Dispatchers.IO` | v1.0 的单文件 addFile 在主线程做流复制，多选放大后 ANR 风险高，本次顺带修复 |
| 行为变化说明 | v1.0 单文件添加成功不弹 Toast；批量成功会弹「已添加 N 个文件」，属需求要求的反馈，有意为之 |

## 四、边界情况

| 场景 | 处理 |
|---|---|
| 系统选择器取消 | `uris == null` → 直接 return，无副作用 |
| 空数组 | `isEmpty()` → return |
| 重复添加同名文件 | 现有 `resolveNameCollision` 自动 `(1)` 后缀，逐文件生效 |
| 部分文件复制失败 | 汇总 Toast「已添加 N 个，M 个失败」，成功文件保留、网格已刷新 |
| 删源失败 | `needPromptDeleteSource` 汇总进 Toast，沿用 v1.0 文案语义 |
| 批量复制期间重复点击 | `isAdding` 防重入 + 按钮 disabled |
| 大文件复制 | 已移到 Dispatchers.IO，UI 不卡顿 |
| item 为 null | Toast「事项不存在」（防御处理，理论上详情页不会发生） |
