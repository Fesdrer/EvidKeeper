# EvidKeeper v1.1 — 计划总览

## 一、版本说明

v1.0 已完成基础应用（事项管理 + SAF 存储 + AI 名称生成）。v1.1 是一个小版本，包含两个需求：

1. **详情页添加文件支持多选**：进入事项后点「添加文件」，系统选择器可一次勾选多个文件（v1.0 为单选）。
2. **设置页可编辑 AI 识别提示词**：v1.0 提示词硬编码在 `GlmApiClient.kt`，现改为设置页可编辑，提供「恢复默认」按钮。

## 二、需求摘要

### 需求一：详情页添加文件多选

- 详情页 `DetailScreen.kt` 的文件选择器从 `ActivityResultContracts.OpenDocument()`（单选）换成 `OpenMultipleDocuments()`（多选），回调返回 `Array<Uri>?`
- `DetailViewModel` 新增批量方法 `addFiles(uris: List<Uri>)`：后台线程（`Dispatchers.IO`）逐文件调用现有 `StorageManager.addFile()`（复用同名 `(1)` 后缀、删源失败标记等全部逻辑），完成后只刷新一次列表，通过现有 `toastMessage` 流汇总结果
- 新增 `isAdding` 进度状态：添加中按钮显示「添加中…」转圈并禁用（防重复点击）
- 大文件复制移到 IO 线程（顺带修复 v1.0 单文件也有的主线程阻塞隐患）
- **明确不改**：新建事项页（CreateScreen）保持单选；`StorageManager` / `AddFileResult` 零改动

### 需求二：设置页可编辑 AI 识别提示词

- 默认提示词常量**单点来源**：从 `GlmApiClient.NAME_PROMPT` 迁移到 `SettingsStore.DEFAULT_NAME_PROMPT`（内容逐字保留，行为不变锚点）
- `GlmApiClient.generateName()` 新增参数 `prompt: String = SettingsStore.DEFAULT_NAME_PROMPT`，空值内部二次兜底；四个私有生成函数（image/pdf/pdf-vision/txt）透传 prompt
- `SettingsStore` 新增 `ai_prompt` 键 + `getAiPrompt()` / `saveAiPrompt()`，空/未设置回退默认
- `SettingsViewModel` 沿用「打开即读、保存才写」draft 模式，新增 `aiPrompt` 草稿 + `resetAiPrompt()`
- `SettingsScreen` 新增多行输入框（≤2000 字，实时计数）+「恢复默认」按钮
- `CreateViewModel` 生成名称时传入 `settingsStore.getAiPrompt()`

## 四、关键约定

| 约定 | 内容 |
|---|---|
| 默认提示词不变 | `SettingsStore.DEFAULT_NAME_PROMPT` 与 v1.0 `NAME_PROMPT` **逐字一致**，不得改动（存量用户行为不变，三保险：默认参数 + getAiPrompt 回退 + generateName 内 ifBlank） |
| CreateScreen 单选 | 新建页文件选择保持单选，不得改为多选（其状态模型是单个 selectedFileUri，AI 生成依赖单文件） |
| StorageManager 不重构 | 批量添加 = 循环复用现有 `StorageManager.addFile()`，不合并成批量方法 |
| 依赖方向 | data 层（SettingsStore）不依赖 network 层（GlmApiClient）；默认常量归设置存储所有 |
| 界面文案 | 全部中文，代码注释中文（与 v1.0 一致） |
| 兼容性 | 无新依赖（OpenMultipleDocuments 为 activity 内建契约；EncryptedSharedPreferences 已在用） |
