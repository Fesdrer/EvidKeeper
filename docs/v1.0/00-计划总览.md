# EvidKeeper — 开发计划总览

## 一、项目简介

EvidKeeper 是一个安卓证据保存应用（Kotlin + Jetpack Compose），用来保存交易截图、回执、发票等重要信息。

信息组织方式：**事项（Item）**。每个事项包含：名称、时间（只含年-月）、若干文件（图片/txt/pdf 等）、是否重要（星标）。

## 二、设计定稿摘要

### 页面结构（共 4 个页面）

1. **主页面**：顶部搜索框 + 右侧 `+`（新建事项）和齿轮（设置）。事项列表从上到下：**重要事项置顶**（黄色五角星），下面普通事项（无星标）。组内按事项时间新→旧，**同年月时按编号从小到大**。每行显示：事项名称（左）、文件数量、星标、时间（右）。
2. **事项详情页**：返回箭头（左）、事项名称（中，点击改名）、星标（右，点击切换重要/普通，黄色↔灰色）、时间（右，点击改年月）。文件以"大图标"网格显示：图片显示缩略图，txt/pdf 显示通用图标 + 文件名。点击文件 → **系统查看器**打开（ACTION_VIEW + FileProvider）。底部居中 `+` → 添加文件。**长按文件** → 菜单：删除（移入回收站）/ 改名（保留扩展名）。
3. **新建事项页**（主页面 `+` 进入）：「添加文件」按钮（选**一个**文件，可选）+ 名称输入框 + 「AI 生成」按钮 + 时间显示框（年-月，默认当前年月，点击可改）。AI 按钮启用条件：已选文件 **且** 已配置 API Key。
4. **设置页**（齿轮进入）：存储文件夹选择、智谱 API Key 输入、AI 模型选择（默认免费版 `glm-4.6v-flash`，可切换正式版 `glm-4.6v`）、保存按钮、返回按钮。**没有回收站入口**（恢复靠系统文件管理器手动操作）。

### 存储结构（用户自选目录 + SAF）

```
存储根/                      ← 用户在设置页选择的文件夹（SAF 授权）
├── remove/                  ← 回收站目录（可恢复、不自动清理）
├── 001-事项名称/             ← 每事项一个文件夹，名称 = 编号-事项名
│   ├── .meta.json           ← 记录：名称、编号、时间(年-月)、是否重要
│   ├── 截图.jpg
│   └── 收据.pdf
└── 002-另一事项/
```

### 关键规则

| 规则 | 内容 |
|---|---|
| 编号分配 | 新建时从 1 开始，取第一个未被根目录事项使用的编号 |
| 排序 | 重要置顶 → 组内时间新→旧 → 编号升序 |
| 改名 | 只改名称部分，编号不变；同步改文件夹名 + meta 文件；创建和改名都要校验非法字符（`\ / : * ? " < > |`），发现即提示用户修改；不得与已有文件夹撞名 |
| 重名处理 | 添加文件时目标文件夹内已有同名 → 自动加 `(1)` 后缀；文件/事项移入 remove 时撞名 → 自动加 `-yyyyMMdd` 后缀 |
| 删除 | 文件删除 → 移入 remove；事项删除 → **整个文件夹移入 remove**（保留结构） |
| 移动文件 | 手机文件移入事项文件夹 = 复制 + 删除原件（SAF 无原子移动）；删除失败时提示"已复制但无法删除原件" |
| 主页面扫描 | 跳过 remove 目录；只把**含 .meta.json 的文件夹**视为事项；meta 缺失/损坏按默认值容错 |
| 时间格式 | 年-月，如 `2026-08`；默认当前年月 |

### AI 名称生成方案（智谱 GLM-4.6V）

- 接口：`https://open.bigmodel.cn/api/paas/v4/chat/completions`，OpenAI 兼容格式，`Authorization: Bearer <key>`
- 模型：`glm-4.6v-flash`（免费，默认）/ `glm-4.6v`（正式版，设置页可切换）
- 三类文件传法（均不需公网托管）：
  - **图片**：`image_url` 字段 base64 编码（`data:image/xxx;base64,...`），单图 ≤5MB，超了先压缩
  - **txt**：本地读文本，作为普通文本消息发送
  - **pdf**：`POST /paas/v4/files`（multipart，`purpose=file-extract`）→ 返回文件 ID → `GET /paas/v4/files/{id}/content` 抽取文本 → 作为文本消息发送
- 注意：`file_url` 仅支持公网 URL **不支持 base64**；一次请求只传一种模态
- 详细实现见 `07-AI名称生成实现.md`

## 四、全局约定

- **包名**：`com.evidkeeper`
- **技术栈**：Kotlin + Jetpack Compose（Material3）+ Navigation Compose + ViewModel（StateFlow）+ SAF（DocumentFile）+ OkHttp + kotlinx-serialization + EncryptedSharedPreferences + Coil（缩略图）
- **SDK**：minSdk 26 / targetSdk 35（用 Android Studio 默认推荐即可）
- **目录骨架**：
  ```
  app/src/main/java/com/evidkeeper/
  ├── MainActivity.kt
  ├── ui/
  │   ├── main/        MainScreen、MainViewModel
  │   ├── detail/      DetailScreen、DetailViewModel
  │   ├── create/      CreateScreen、CreateViewModel
  │   ├── settings/    SettingsScreen、SettingsViewModel
  │   └── components/  公共组件（含 YearMonthPickerDialog）
  ├── data/
  │   ├── model/       数据模型
  │   ├── storage/     StorageManager（SAF/DocumentFile 全部文件操作）
  │   └── settings/    SettingsStore（URI、API Key、模型选择持久化）
  ├── network/         GlmApiClient（AI 调用）
  └── util/            工具（MIME 判断、base64、压缩等）
  ```
- **主题**：Material3；重要星标黄色 `#FFD700`，普通星标灰色（如 `#9E9E9E`）
- **界面文本全部中文**；代码注释用中文（与用户 Karma 项目习惯一致）
