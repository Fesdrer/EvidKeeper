# 步骤 3：主页面 UI

> 目标：主页面完整 UI + 导航接通。**搜索框只建 UI，过滤逻辑留到步骤 6**（本步搜索框可输入，但输入不影响列表）。
> 前置：步骤 2 完成（本步使用 StorageManager 和 SettingsStore）。

## 一、界面布局

```
┌───────────────────────────────────────┐
│ (搜索框)                       [+][⚙] │   ← 顶部栏
├───────────────────────────────────────┤
│ 重要事项1    [3个文件] ★ 2026-08   │   ← 黄色星标（重要）
│ 重要事项2    [2个文件] ★ 2026-07   │
│ 事项1        [1个文件]     2026-08   │   ← 无星标（普通）
│ 事项2        [5个文件]     2026-06   │
│ ...                                  │
└───────────────────────────────────────┘
```

- 顶部一行：搜索框（TextField，占满剩余宽度，带放大镜图标和清除按钮）、`+` 按钮（导航到新建页）、齿轮按钮（导航到设置页）。
- 列表（LazyColumn）：**不分组标题**，重要事项自然排在前面（数据层已排好序）。
- 每行布局：事项名称（左侧，单行省略）→ 文件数量（小字，如 `3个文件`）→ 星标图标（重要=黄色 `#FFD700`，普通=灰色 `#9E9E9E`；主页面星标**只显示不可点**）→ 时间（右侧，格式 `2026-08`）。
- 空态：无任何事项时显示居中提示"还没有事项，点右上角 + 新建"。

## 二、交互

1. **点击事项行** → 导航到详情页（传事项 id，或传文件夹 Uri + id，二选一，注意详情页刷新问题——建议传 id，进详情页后按 id 重新扫描取数据）。
2. **长按事项行** → 弹出菜单（DropdownMenu 或类似）：
   - **改名**：弹 AlertDialog + 输入框（预填当前名称）。校验：非空、不含非法字符（`\ / : * ? " < > |`，发现即提示"名称不能包含这些字符：\ / : * ? \" < > |"）、不与现有文件夹撞名（StorageManager.renameItem 返回失败原因时展示）。成功 → 刷新列表。
   - **删除**：确认对话框（"确定删除事项「xxx」？所有文件将移入回收站"）→ `StorageManager.deleteItem` → 刷新列表。
3. **`+` 按钮** → 导航到新建页（步骤 5）。
4. **齿轮按钮** → 导航到设置页（步骤 5）。
5. **回到主页面时刷新**：`LaunchedEffect` 监听 `ON_RESUME`（或导航返回时触发），重新扫描列表。

## 三、代码结构

- `ui/main/MainViewModel.kt`：
  - `val items: StateFlow<List<Item>>`（已按规则排好序）
  - `fun load()`：调 StorageManager.listItems() 并排序
  - `fun renameItem(item, newName)`、`fun deleteItem(item)`（内部调 StorageManager，成功后 load()）
  - **本步暂时没有 query 状态**（搜索的 query 状态放到步骤 6 加）
- `ui/main/MainScreen.kt`：上述布局 + 对话框 + 导航回调（`onOpenDetail(id)`、`onOpenCreate()`、`onOpenSettings()`）。
- 导航：`MainActivity.kt` 中搭 `NavHost`，注册 4 个目的地：`main`（完成）、`detail`、`create`、`settings`（后三个本步只放占位空屏，步骤 4/5 填充）。
